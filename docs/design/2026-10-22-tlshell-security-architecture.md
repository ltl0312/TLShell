## 0. 系统画像

### 0.1 六个必须承认的事实

1. **TLShell 的安全等级等于用户本身**。`asInvoker` 不降权（继承父令牌），shell 子进程与 TLShell 同 IL、同用户，**中间没有任何强制边界**。shell 被植入的东西能做的一切，TLShell 都能做，反之亦然。
2. **零网络、无远程输入**。无更新器、无遥测、无 IPC 服务、无 Tauri/IPC、无插件、不监听端口。这削掉了远程可利用面，也意味着**没有远程代码执行路径**——所有攻击者都需要先有同用户代码执行或诱导用户。
3. **主攻击面是四类解析器**：`vte`（不可信字节流）、`fontdue`（字体）、Win32 消息（任意同 IL 进程可投递）、TOML/JSON 配置（可写即代码）。
4. **用户从浏览器粘贴的命令是信任链最薄的一环**，不是 VTE 内存破坏。`randomstr.ps1`、`iwr | iex` 这类攻击每次都先经过"用户看见并确认"这一步，所以**可见性、粘贴语义、剪贴板完整性**比 fuzzing 更值钱。
5. **可见性缺失是系统性风险**。桌面层 + 零 chrome + 无托盘 + 无关闭按钮 + 可配到 `opacity = 0.30`：**一个正在运行、可能是管理员的 shell，可以做到桌面上几乎不存在**。用户不会攻击自己看不见的东西，也不会防御自己忘了的东西。
6. **UIPI 只在 IL 不等时生效**。medium→high 被挡；**同 IL 全部放行**。所有"不可信进程"都按同用户处理。

### 0.2 威胁优先级（结合已冻结决策重排）

| # | 威胁 | 现实度 | 后果 | 位置 |
|---|---|---|---|---|
| 1 | 终端内执行恶意命令（粘贴/`iwr\|iex`/`npm postinstall`/typosquat） | 高 | 中(用户 IL)-高(提权态) | 6.5 / S-01 / S-20 |
| 2 | 用户看不见窗口 → 忘记在跑的提权 shell | **高** | 高 | S-07 / S-20 |
| 3 | 剪贴板污染（OSC 52 / 复制进历史与云同步 / 粘贴多行直执行） | 高 | 中 | S-05 / 6.5 |
| 4 | WorkerW 父窗口冒充 | 低 | 高（输入改投） | S-02 |
| 5 | 相对路径二进制种植 / env 继承 | 中 | 高 | S-03 |
| 6 | 子 shell 残留 + 无关闭按钮 → 长期无窗口 shell | 中 | 中-高 | S-04 / S-20 |
| 7 | `vte`/`fontdue` 内存破坏 | 低 | 高 | 6.6 |
| 8 | 配置/状态文件篡改 | 中 | 中-高 | S-08 / S-09 |

## 1. 信任边界

```
   ┌──────────── 用户（唯一授权主体）────────────┐
   │                                            │
   ▼ 键盘/IME/鼠标                     剪贴板 ▼ ▼ 屏幕
┌──────────────────────────────────────┐  ┌──────────────┐
│ B1 Win32 输入 + IME                  │  │ B7 剪贴板     │
└───────────────┬──────────────────────┘  └──────┬───────┘
                ▼                                ▼
        ┌───────────────────────────────────────────┐
        │  TLShell 进程（medium/high IL，同用户）    │
        │  ┌──────────┐  ┌──────────┐  ┌─────────┐  │
        │  │ 核心     │←→│ 呈现     │  │ 配置     │  │
        │  │ Term/输入│  │ 帧合成   │  │ TOML/JSON│  │
        │  └────┬─────┘  └────┬─────┘  └────┬────┘  │
        └───────┼─────────────┼─────────────┼───────┘
          B3 写 │        B5 绘│        B6 读│
                ▼             ▼             ▼
      ╔══════════════════╗  ┌────────┐  ┌─────────────┐
      ║ B3/B4 ConPTY     ║  ║ B2 桌面 ║  ║ B6 文件系统  ║
      ║ （内核对象）      ║  ║ 窗口消息║  ║(用户可写目录)│
      ╚═════════╤════════╝  ╚════════╝  └─────────────┘
                ▼
        ┌────────────────┐   ┌──────────────┐
        │ shell 子进程    │   │ B8 字体       │
        │（同 IL、同用户）│   │（内置=零输入）│
        └────────────────┘   └──────────────┘

   B10 网络：不存在（非"受控"，是"无代码路径"）
   B11 子进程生命周期：Job Object 单向约束
```

| 边界 | 方向 | 内容 | 信任级别 | 强制手段 |
|---|---|---|---|---|
| **B1** 输入/IME | 入 | 键、UTF-16 `WM_CHAR`、IME 组合串 | 用户可控，视为授权动作 | 单一来源（见 S-12）；IME 结果按文本处理，不按字节序列 |
| **B2** 窗口消息 | 入 | `WM_*`、`TaskbarCreated` 广播 | **不可信**（同 IL 任意进程可 Post） | 只接受参数化消息；不解析任何指针载荷；不携带命令 |
| **B3** 核心→PTY 写端 | 出 | VT 字节流 | 出站命令通道 | 唯一写入口；粘贴/OSC 52 在这里过滤 |
| **B4** PTY 读端→vte | 入 | 任意字节（含 ESC/OSC/DCS/CSI） | **不可信** | `vte` 边界；OSC 52 在 `EventListener` 层丢弃 |
| **B5** 网格→屏幕 | 出 | 字形、颜色、控制字符效果 | 出站，**语义级信任用户** | 视觉欺骗缓解（S-11），不做内容审计 |
| **B6** 存储 | 双向 | `config.toml`、`state.json`、日志 | **不可信**（可写=代码） | 白名单 schema + 范围校验 + 原子写 + 不跟随重解析点（6.2） |
| **B7** 剪贴板 | 双向 | 文本 | **不可信**（进出都脏） | 写入默认拒绝/显式允许；读取一律按未净化文本 |
| **B8** 字体 | 入 | 字形/度量 | **已消除运行时输入** | `include_bytes!` 内置（UI §3.1.1）→ 无用户可写字体文件 |
| **B9** 单实例 IPC | 双向 | "显示/聚焦"、`--quit` | **不可信**（冒名可 DoS） | 消息体只允许枚举值；不做命令通道（S-17） |
| **B10** 网络 | — | 无 | — | 0 个 socket；`[features] default = []`（S-16） |
| **B11** 子进程生命周期 | 出（约束） | Job Object 成员 | 单向 | `KILL_ON_JOB_CLOSE`（不变量 7） |

**三条跨边界不变式**

1. **B1/B2 → B3 是唯一的命令注入点**。任何绕过 `term/session.rs` 写 PTY 的代码路径都是缺陷。
2. **B4 的内容永远不许变成 B3 的动作**，唯一例外是被显式列入白名单的 OSC 52 且策略允许（6.5）。
3. **B5 的视觉效果不许被 B4 的内容用来改变窗口行为**（不改标题、不改位置、不改透明度、不触发 resize）。

## 2. 进程与权限模型

| 项 | 决定 |
|---|---|
| 进程数 | 1（UI + 1 PTY 读线程 + `WM_TIMER` 驱动；无子进程代理、无 helper、无 broker） |
| 完整性级别 | `asInvoker`（继承父令牌），**不请求提权、不请求 UIAccess** |
| 提权态 | 可能为 high IL（见 §3），**必须可见** |
| 令牌特权 | shell 必须能正常工作，不能 `CreateRestrictedToken` 剥特权（剥 `SeChangeNotify` 之外的任何东西都可能让 `git`/`npm` 失败） |
| 句柄策略 | 自有句柄不继承；给子进程的只有 ConPTY 管道 + std 三个；建 PTY 时 `bInheritHandles` 用显式句柄列表 |
| 子进程创建 | `CreateProcessW(shell_abs_path, args, …, bInheritHandles=FALSE, EXTENDED_STARTUPINFO_PRESENT, env, cwd)`：绝对路径、显式 env、固定 cwd（S-03） |
| 生命周期 | `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`（不变量 7）；`New`/`--quit`/关闭都走同一个 `shutdown_session()`（S-20） |
| 网络 | 零。仅当 M5 做 SSH 才新增，且届时重新评审 B10 |
| 自启动 | v1 **不做**（Run 键 = 常驻可见终端 + 用户不知情，与 §0.1-5 冲突） |
| 自动更新 | 不做（会重新引入网络通道 + 代码执行路径，见 S-19） |
| 降级路径 | WorkerW 挂载失败 → 普通无边框窗口（分辨率最高、行为最可预测） |

**不做沙箱的理由**：终端沙箱化 = shell 做不了事。AppContainer 下 `git`/`npm`/`ssh`/系统管理全部失败，等于产品失去意义。**TLShell 的定位不是给不可信 shell 加壳，而是给可信 shell 一个更好的宿主**——因此防御重心在 §0.2 的 1–6，不在 7。

## 3. 提权模型（决策已冻结）

### 3.1 三层事实

1. **终端里的子进程不能自行提权**。要管理员的程序（`services.msc`、注册表编辑器、`net session`）触发 UAC 并在**新的控制台窗口**运行，不在本 PTY 内。计划书原 §7「管理员程序：PTY 仍可工作」**不成立**——它对"用户在 PTY 里跑管理员程序"和"TLShell 自己是管理员"做了错误合并。
2. **`asInvoker` 不会降权**。从管理员 shell 启动 TLShell → TLShell 是 high IL → **它起的每一个 shell 都是管理员**。用户按过一次"以管理员身份运行"，之后所有会话都是管理员，且零 chrome 下没有任何提示。
3. **`uiAccess="true"` 会引入 UIAccess 特权**（可把输入投递给更高 IL 窗口、可绕过部分 UIPI），**恒为 false**。

### 3.2 冻结决策（用户，2026-10-22）

**不拒绝启动，改为"提权态必须可见"**。理由：用户会从管理员终端启动 TLShell 是合理工作流，拒绝启动等于拒绝该工作流；而"特权存在但不可见"才是真风险。

### 3.3 落地要求

| # | 要求 |
|---|---|
| 1 | manifest 恒 `level="asInvoker" uiAccess="false"`；**不调用** `ShellExecuteEx(runas)`、不做"以管理员重启" |
| 2 | 启动 `GetTokenInformation(TokenElevation)` → `Token.IsElevated`，结果存 `AppState.elevated` |
| 3 | high IL：描边常驻 `elevated_ring`、overlay 常驻 `ADMIN`，**固定在 L4、alpha 1.0、不随 `opacity` 稀释**（UI §4.2.1） |
| 4 | 首次以 high IL 运行时，在 §4.6 的一次性提示里追加一行：`当前为管理员会话，子进程继承管理员权限` |
| 5 | `TLShell.exe --status` 输出 `elevation: medium\|high`，供脚本与排障 |
| 6 | 提权态**不改变**其他任何行为（不换主题、不换字体、不禁用功能）——只做标注 |

### 3.4 连带影响（S-20，必须一并处理）

提权态一旦可见，"`New` 重开会话"就多了一层语义：**它是以当前 IL 重生 shell**。high IL 下双击 `New` = 用两次鼠标点击把 medium 会话升级成管理员会话。角标已经常驻，语义自洽，但要求：

1. `New` 的 armed 态必须在**鼠标离开按钮 / 窗口失焦 / 任意按键**时立即复位，否则"点一下、去倒水、回来再点一下"就是合法双击（UI §4.4 已定 1.5s 超时，需补这三条复位条件）。
2. 终止必须走 `shutdown_session()`：`ClosePseudoConsole` → `WaitForSingleObject(job, 3s)` → 未退则 `TerminateJobObject`。**不得**只 `TerminateProcess(shell_pid)`，否则 `powershell → cmd → 孙进程` 残留（S-04 同源）。

## 4. 敏感数据流

| # | 流 | 数据 | 风险 | 控制 |
|---|---|---|---|---|
| D1 | 键盘 → VT 字节 | 口令、路径 | 明文在内存；崩溃转储 | 不落盘；转储默认关；输入不写日志 |
| D2 | IME → 组合串 → PTY | 中文输入 | 组合串双份（preedit + commit）可能重复投递 | 只投递 commit；preedit 仅绘制 |
| D3 | `WM_CHAR` → PTY | UTF-16 码元 | **代理对拆成两个半字符**写入 PTY | 按 grapheme 重组后再编码（S-12） |
| D4 | PTY → `vte` → 网格 | 任意字节 | 内存破坏；视觉欺骗；OSC 52 | `vte` 边界 + OSC 52 默认丢；Bidi/RLO 处置（S-11） |
| D5 | 网格 → DIB → 屏幕 | 全部可见内容 | 全屏捕获/投屏/录屏；`opacity=0.30` 时"不可见但仍在跑" | `SetWindowDisplayAffinity` 对子窗口**无效**，如实写 README；提权标注不稀释（S-07） |
| D6 | 选区 → 剪贴板 | 命中/路径/IP/密钥片段 | 进剪贴板历史、云同步、RDP 重定向；被误当命令粘贴 | 显式动作才写；默认排除历史与云（6.5-2） |
| D7 | 剪贴板 → PTY（粘贴） | 任意文本 | 多行直接执行 = 最常用投递手段 | 净化 + bracketed paste + 多行二次确认（6.5-3） |
| D8 | 配置读 | 执行策略 | 可写即代码：`shell.path` 任意 exe | 白名单 + 拒绝 UNC/相对路径 + 越界钳制 + 原子写（6.2） |
| D9 | 状态读 | 窗口位置 | 篡改成 (0,0) 或屏外 → "窗口丢了" | 校验坐标空间 + 与显示器求交 + 回中（S-08） |
| D10 | 日志写 | 命令、路径 | 落盘泄漏；换行注入伪造日志 | 默认只记会话生命周期；不记输入；所有字段转义（S-10） |
| D11 | `%LOCALAPPDATA%` | 配置+状态 | **明文可读**（不加密） | 明确写"不加密"；目录 ACL 靠用户 profile；不放凭据 |
| D12 | `--quit` 信号 | 会话终止 | 任意同用户进程可终止会话（DoS） | 接受（同 IL 本就能）；不携带命令 |
| D13 | 环境变量 → shell | `AWS_*`、`GITHUB_TOKEN`、代理 | 全量继承把密钥送进每个 shell，再被 `env`/崩溃日志/子进程泄漏 | 白名单 + `[env]` 显式注入（6.2-2） |

## 5. 最小权限

### 5.1 进程与令牌

1. manifest 恒 `asInvoker` + `uiAccess="false"`；永不自动提权（§3.3）。
2. 不创建服务、不装驱动、不加计划任务、不改注册表启动项（v1）。
3. 不请求 `SeDebugPrivilege`/`SeImpersonate`/`SeTcb`；**唯一需要的特权是默认就有的**。
4. 不 `AdjustTokenPrivileges` 增删任何特权。
5. 单实例互斥体只做"聚焦"，**不承载命令**（S-17）。

### 5.2 文件系统

1. 只写 `%LOCALAPPDATA%\TLShell\`（config/state/log），**不写程序目录、不写 `%APPDATA%`（漫游）**。
2. 打开自身文件用 `FILE_FLAG_OPEN_REPARSE_POINT`，拒绝跟随重解析点（防把 config 换成指向别处的 junction）。
3. 写入一律 `MoveFileEx(MOVEFILE_REPLACE_EXISTING|MOVEFILE_WRITE_THROUGH)` 原子替换；`state.json` 高频写用"临时文件 + 重命名"。
4. 不读用户文档、不索引磁盘、不做"最近目录"之类的便利功能。
5. 日志目录**不做**轮转之外的清理；单文件上限（如 4MB）+ 保留 3 份。

### 5.3 网络

1. **0 个 socket**。`[features] default = []`，禁止任何 crate 默认启用 `native-tls`/`reqwest`/`hyper`。
2. CI 加一条检查：`cargo tree` 里出现 `socket2`/`mio`/`tokio` 即失败（除 `portable-pty` 自身已用的最小集）。
3. 不做更新检查、不做 telemetry、不做 crash 上报。

### 5.4 子进程

1. 绝对路径 + 显式 env 白名单 + 固定 cwd（S-03）。
2. Job Object 绑定，`KILL_ON_JOB_CLOSE`（不变量 7）；`shutdown_session()` 单点（§3.4）。
3. 不给 shell 传任何 TLShell 内部状态（会话 ID、路径、配置内容）作为参数或 env。
4. 不做"以管理员运行选中命令"之类的便利功能——那等于把 §3.3 的可见性控制自己绕过去。

### 5.5 剪贴板与粘贴（决策已冻结）

**(1) 复制：有选区复制 + 二次提示**

| 项 | 规格 |
|---|---|
| 触发 | `Ctrl+Shift+C`、`Ctrl+Insert`、右键（有选区时） |
| 动作 | 写 `CF_UNICODETEXT`，**同一份文本只写一次**（避免重复写触发两次历史条目） |
| 提示 | 一次性 toast：`已复制 N 字符`，1.2s 淡出，画在 overlay（不写 PTY、不动网格） |
| 历史/云 | 写剪贴板后调用 `ExcludeClipboardContentFromMonitorProcessing()`；同一次 `OpenClipboard` 内设 `CanIncludeInClipboardHistory = 0`、`CanUploadToCloudClipboard = 0`；`SetClipboardData` 后再设一次（顺序反了会被忽略） |
| 失败 | `OpenClipboard` 被占用 → 重试 3 次 ×50ms → 静默失败 + toast `复制失败`（不弹窗） |

"(2) 粘贴：**冻结为"不阻断，但要可见"**"

不做二次确认弹窗（决策 4）：v1 不做完整粘贴**功能**，但**必须**做以下四件，否则 `Shift+Insert`/右键/`WM_PASTE` 会变成无提示的裸粘贴：

1. **拒绝一切非文本格式**：只读 `CF_UNICODETEXT`；`CF_HDROP`/HTML/RTF 存在时不拼装、不猜测。
2. **净化**：去掉 `\0`、`\r`（归一为 `\n`）、`\x1b` 及 C0/C1 控制符与 `DEL`；保留 `\t` `\n`。（粘贴一段带 ESC 的文本可以改光标、改标题、伪造提示行——必须剥掉。）
3. **多行 = 可见警示 + 一次确认**：行数 ≥ 2 或长度 > 1024 时，**第一次** `Shift+Insert` 不发送任何字节，改为在网格上方浮出一条提示：`粘贴 N 行？再按一次 Shift+Insert 确认`（3s 失效）。第二次才发送。这是"不阻断但可见"的最小实现，比弹窗轻，比裸粘贴安全。
4. **bracketed paste**：shell 开启时用 `ESC[200~ … ESC[201~` 包裹（vte 层已支持 `BracketedPaste` 模式位），使 `readline`/PSReadLine 不逐行执行。

验收：① 从网页复制含 `\x1b[2J` 的文本粘贴 → 屏幕**不**被清；② 粘贴 3 行命令 → 出现确认提示，未直接执行；③ 复制后 `Win+V` 历史里**没有**该条目；④ 复制含中文 → 长度按字符计（非字节）。

**(3) OSC 52：默认拒绝，显式允许**

- `vte` 的 `EventListener` 收到 OSC 52 set 时**直接丢弃**，并在**首次**遇到时于网格上方浮一行 dim 提示：`终端请求写入剪贴板，已拒绝（config: clipboard.allow_osc52）`。
- `clipboard.allow_osc52 = true` 时才执行，且**只允许写入、不允许读取**（OSC 52 的 read 查询恒不响应）。
- 理由：`cat` 一个恶意文件、`ssh` 到被控机器、`git diff` 一个恶意 patch，都能静默替换剪贴板——用户下一次 `Ctrl+V` 就粘到攻击者内容。

### 5.6 字体

`include_bytes!` 内置 Sarasa Term SC（UI §3.1.1）把 B8 从"读用户可写目录的字体文件"降级为**零运行时输入**——这是净收益，写在这里以免下个版本为了减包体又改回外部字体。若改回外部字体：必须校验 sha256 + 只从程序目录读 + 拒绝重解析点。

### 5.7 屏幕与可见性（S-07 的控制）

1. 提权描边/`ADMIN` 标注固定 L4、alpha 1.0（§3.3-3）。
2. README 明确：内容对全屏捕获、投屏、录屏可见；`SetWindowDisplayAffinity` 对 `WS_CHILD` 子窗口无效（不要写成"支持防截屏"）。
3. `opacity` 越界钳制 + 首次提示 + `--status` 输出当前 `opacity`（见 6.4-16）。
4. v1.5 可选：`opacity < 0.45` 且 30 分钟无输入 → 描边呼吸提示。v1 只写"已知限制"。

### 6.1 `Ctrl+C` 状态机（决策 3 冻结）

```
Ctrl+Shift+C  有选区 → 复制 + toast；无选区 → 透传给 shell（不额外发 0x03）
Ctrl+C        有选区 → 只清除选区（不发字节）
              无选区 → 发送 0x03（中断）
Ctrl+Insert   复制（Windows 惯例，始终生效）
Shift+Insert  粘贴（受 §5.5-2 约束）
右键          无菜单：有选区 → 复制；无选区 → 粘贴（受 §5.5-2 约束）
```

**不变式**：① `0x03` 永远有可达按键（`Ctrl+C` 无选区）；② 复制与中断**不共用同一次按键语义**——一次按键只做一件事。

**验收**：vim 内 `Ctrl+C` 必须打断当前命令；有选区时第一次 `Ctrl+C` 只清选区、第二次才打断。这条验收必须在 M5 关掉前跑过，否则中断功能是"看起来有"。
