## 0. 评审结论

计划书的「零 chrome 单窗口单会话」方向成立，桌面层终端不该有标题栏、标签条、状态栏。但有 **6 处缺口会让现有验收动作无法判定**，必须在对应里程碑补齐，否则 M1/M2/M4 的「通过」只是主观感受。

| # | 缺口 | 阻断的验收 | 归属 |
|---|---|---|---|
| G1 | 只定义了 3 个颜色，ANSI 16 色未定义 | M1-④ `Get-ChildItem` ANSI 颜色正确 | M1 |
| G2 | CJK fallback 字体度量未定义 | M1-⑥ 中文表格对齐 | M1 |
| G3 | 焦点态无可视反馈 | M2-② 「点击后可继续输入」不可判定 | M2 |
| G4 | `border_radius` 与 `SetLayeredWindowAttributes` 能力互斥 | R4 / M4-④ 圆角验收 | M4 |
| G5 | 退出只有全局热键，且热键可能注册失败 | §7 退出方式 | M0 |
| G6 | 无「窗口找不回来」的恢复路径 | M3-④ 坐标钳制的反面 | M3 |

G1/G2 是**渲染正确性**问题（不做则 M1 无法通过），G3/G4 是**视觉规范与实现能力对齐**问题，G5/G6 是**恢复路径**问题。

## 1. 设计不变量（先定不可协商项）

1. **文字永远不参与透明度稀释**。背景可透，字形不可透。
2. **网格是唯一布局单位**。任何视觉元素只能落在整格上，或作为不参与布局的 overlay。
3. **焦点态必须可见**。桌面层窗口没有标题栏，焦点态是用户唯一能判断「能不能打字」的依据。
4. **零常驻 chrome**。不占网格区域的 UI 只在 hover / 首次运行时出现，且必须能自动消失。
5. **配置项必须有可见效果**。不允许存在「写了但无效果」的配置键（当前 `border_radius` 违反此条）。

## 2. 配色规范

### 2.1 语义槽位（v1 必须齐全）

计划书只给了 `background / foreground / cursor` 三个键。终端渲染实际需要以下槽位，缺任一都会落到不可控默认值。

| 槽位 | 默认值 | 用途 |
|---|---|---|
| `background` | `#1e1e2e` | 内容区底色 |
| `foreground` | `#cdd6f4` | 默认前景 |
| `cursor` | `#f5e0dc` | 光标块填充 |
| `cursor_text` | `#1e1e2e` | 光标块内字符（反色） |
| `selection_bg` | `#585b70` | 选区填充 |
| `selection_fg` | `#cdd6f4` | 选区文字 |
| `focus_ring` | `foreground` @ 24% | 有焦点时的 1px 内描边 |
| `ansi[0..16]` | 见 2.3 | ANSI 基础色 |

### 2.2 对比度基线

| 组合 | 比值 | 判定 |
|---|---|---|
| `#cdd6f4` on `#1e1e2e` | **11.4 : 1** | 远超 AA |
| `#f5e0dc` on `#1e1e2e` | 13.0 : 1 | 光标块可辨 |
| `#1e1e2e` on `#f5e0dc` | 13.0 : 1 | 反色字符可读 |
| `#cdd6f4` on `#f5e0dc` | **1.14 : 1** | ⚠ 不可用，见下 |

**硬规则**：块状光标必须把格内字符用 `cursor_text` 重绘（反色）。若直接把前景色字符画在光标块上，1.14:1 等于字符消失。

### 2.3 ANSI 16 色调色板

取 Catppuccin Mocha，但 **ANSI 0 与 8 必须偏离官方值**：

| idx | 官方 Mocha | on `#1e1e2e` | 采用值 | 采用后比值 |
|---|---|---|---|---|
| 0 black | `#45475a` | **1.8 : 1** | `#9399b2` | 5.8 : 1 |
| 8 br.black | `#585b70` | 2.5 : 1 | `#9399b2` | 5.8 : 1 |
| 1 red | `#f38ba8` | 8.2 : 1 | 同官方 | — |
| 2 green | `#a6e3a1` | 10.9 : 1 | 同官方 | — |
| 3 yellow | `#f9e2af` | 12.5 : 1 | 同官方 | — |
| 4 blue | `#89b4fa` | 8.9 : 1 | 同官方 | — |
| 5 magenta | `#f5c2e7` | 11.4 : 1 | 同官方 | — |
| 6 cyan | `#94e2d5` | 11.6 : 1 | 同官方 | — |
| 7 white | `#bac2de` | 8.9 : 1 | 同官方 | — |
| 9–15 | 官方 bright | 均 ≥ 7 : 1 | 同官方 | — |

ANSI 0/8 在 Mocha 基色上做文字只有 1.8:1，`Get-ChildItem` 里任何用黑色标注的项都会糊掉。M1-④ 若用官方值验收必然有争议，**先按上表替换**，并在 README 注明这是对 Catppuccin 的有意偏离。

### 2.4 透明度

- 有效区间钳制到 **[0.75, 1.0]**。低于 0.75 时，全局 alpha 会同时稀释文字与背景，在浅色壁纸上正文对比度跌破 4.5:1（白壁纸实测 0.5 档约 2:1），不满足可用性下限。
- 默认 0.88 在白壁纸上正文仍有约 8.2:1，可用。
- 若走逐像素 alpha（见 2.5），可放开到 0.5，因为只有背景透、文字不透。

### 2.5 圆角与透明度的实现路径（G4）

`WS_EX_LAYERED` + `SetLayeredWindowAttributes(alpha)` 是**整窗统一 alpha**：文字一起变半透，且无法做圆角（除非用 color key，而 color key 与 alpha 互斥）。

| 路径 | 圆角 | 文字不透明 | 代价 |
|---|---|---|---|
| A. `SetLayeredWindowAttributes` | ✗ | ✗ | 0（计划书当前方案） |
| B. 自绘 DIB + `UpdateLayeredWindow` 逐像素 ARGB | ✓ | ✓ | +1～2 天 |

**建议**：M4 走 B。理由：A 的文字在浅壁纸上发灰是可感知的画质损失，与 R4「文字清晰」直接冲突；且 A 无法兑现 `border_radius` 配置项。

**若 M4 决定走 A**：必须从 `config.toml` 删除 `border_radius`，把圆角列入 v2。不允许「配置项存在但无效果」。

## 3. 排版与网格规范

### 3.1 字体

| 项 | 值 | 说明 |
|---|---|---|
| 主字体 | `Cascadia Mono` | 等宽，ASCII 覆盖好 |
| CJK fallback | `Sarasa Mono SC` | **关键**：设计上 CJK advance 恰为 2×ASCII |
| 次选 fallback | `Microsoft YaHei UI`（按比例缩放字号） | 仅在无 Sarasa 时 |
| 字号 | 14.0 DIP | 配置项 |
| 行高 | 1.25 em = 17.5 DIP | 配置项 |
| Emoji | **不支持** | fontdue 只出 alpha 位图，彩色 emoji 会成豆腐块 |

### 3.2 CJK 对齐（G2）

`Cascadia Mono` 不含 CJK 字形，中文会 fallback。若 fallback 字形的 advance ≠ 2 × ASCII advance，`printf` 式表格与 `Get-ChildItem` 的列对齐必然错位——这正是 M1-⑥ 的验收点。

规范：

1. 优先选 `Sarasa Mono SC` / `Sarasa Term SC`（专为「CJK = 2 格」设计）。
2. 无 Sarasa 时，对 fallback 字体做**字号缩放**：`cjk_px = font.size × 2 × ascii_advance_em / cjk_advance_em`，使 advance 强制等于 2 格。
3. 全角标点、`※`、`①②` 等 ambiguous-width 字符按 East Asian Width 判定：`W`/`F` → 2 格，`A` → 1 格（与 Windows Terminal 一致）。
4. 组合字符 / 变体选择符按 grapheme cluster 合成到一个格内，不得逐码点占格。

### 3.3 网格几何

- **cell 尺寸必须取整到物理像素**。14px @ 125% DPI 的 advance 约 10.25px，若保留小数会累积漂移，右边缘出现字形抖动。
- 行高同样取整。
- 换算点唯一：`render/layout.rs`。字号是 DIP，cell 是物理像素，DPI 变化只改 layout，不改 glyph cache 的键。
- 参考值（900×420、padding 10、100% DPI）：cell ≈ 8×17，内容区 880×400 → **110 列 × 23 行**；125% DPI 下约 **86 列 × 19 行**。

### 3.4 内边距

- `padding = 10` 四边等值时，文字顶部视觉偏挤（无标题栏承担呼吸感）。建议默认 **`padding = 12`，且顶部比底部多 2px**，或统一 10 但在 layout 里给首行加 2px 顶偏移。
- padding 计入 layout，不参与 hit-test（边缘 6px 仍归缩放区）。

### 3.5 最小尺寸

- 建议 **480 × 240**（约 58 列 × 13 行 @100%）。低于此值 `Get-ChildItem` 表格已不可读，且 v2 分屏无最小可读单元。
- 最大尺寸钳制到 WorkerW 客户区。

## 4. 布局与状态规范

### 4.1 v1 可见层级

```
┌─────────────────────────────────┐  ← 无边框，圆角 8（路径 B 才有）
│  padding 12                     │
│  ┌───────────────────────────┐  │
│  │ 网格（唯一布局单位）        │  │  ← 110×23 cell
│  │                           │  │
│  └───────────────────────────┘  │
│                        [×] ←overlay，hover 才出现
└─────────────────────────────────┘
```

只有两层：**网格层** + **overlay 层**（不占布局）。overlay 层包含：hover 控制条、IME 候选、首次运行提示。

### 4.2 焦点态（G3）

| 状态 | 光标 | 描边 |
|---|---|---|
| 有焦点 | 实心块，`cursor` 填充 + 字符反色，闪烁 530ms | 1px 内描边，`focus_ring` |
| 无焦点 | 1px 空心矩形，不闪 | 无描边 |

这是 Win+D 后「能不能直接打字」的唯一反馈。**从 M2 起必须实现**，不能推到 M5 打磨。

### 4.3 拖动 / 缩放 affordance

零 chrome 下没有可见边框，用户不知道哪里能拖。用 **cursor shape** 做零成本 affordance：

| 命中区 | 光标 | 行为 |
|---|---|---|
| 边缘 6px | `IDC_SIZEWE` / `SIZENS` / `SIZENWSE` 等八向 | 缩放 |
| 顶部 8px 条 | `IDC_SIZEALL` | 拖动 |
| 其余 | `IDC_IBEAM` | 文本选择 / 输入 |

可选增强：hover 边缘时绘制 1px `focus_ring` 描边，明确缩放边界。

### 4.4 退出与恢复（G5 / G6）

- `Ctrl+Alt+Q` 是**全局热键**，`RegisterHotKey` 可能因被占用而失败 → 注册失败时进程无退出路径。必须双通道：hover 时右上角浮出 24×24 的 `×`（背景 `background` @ 90%，圆角 6，进入 1.5s 淡入、离开 0.8s 淡出），同时热键注册失败要写日志并在首次运行提示里告知。
- 窗口拖到不可见区域后无托盘可找回。补 `TLShell.exe --reset-position`，并在启动时若还原后矩形与任一显示器无交集则回中。
- 首次运行提示（一次性，3s 淡出，用 ANSI dim 色画在网格底部，PTY 有输出即消失）：`拖动边缘缩放 · 拖顶部移动 · Ctrl+Alt+Q 退出`。

### 4.5 IME（M5 预留）

中文输入时 preedit 串必须在光标处绘制（下划线 + 候选窗跟随），否则用户看不到正在输入什么。预留 `ImeOverlay` 组件位，即使 M5 前不实现也要在 painter 的合成顺序里留出层级。

## 5. v2 代数预留（标签页 / 分屏 / 状态栏 / 快捷键提示）

v1 不实现，但结构不能阻碍 v2。以下是**布局代数**，不是排期。

### 5.1 布局模型

窗口 = **面板树**（split tree），叶 = session view。标签页 = 面板树上的「多根」层。

```
Window
 └ TabSet (v1 恒为 1 个 tab，不渲染标签条)
    └ Pane (v1 恒为单叶)
       └ SessionView = 网格 + overlay
```

v1 的 `app.rs` 只持有单个 `SessionView`；v2 在它外面套 `Pane`/`TabSet`。这样 v1 不需要写任何占位代码，只需保证「网格渲染不假设自己占满客户区」。

### 5.2 视觉规则（v2 生效）

| 元素 | 规格 |
|---|---|
| 标签条 | 高 28px，背景比内容区暗 8%；活动标签与内容区**同色**形成连通，非活动标签用 1px 下边线断开 |
| 标签标题 | 取 shell 名或 cwd 尾段，最多 18 字符，超出中段省略 |
| 分屏分隔条 | 6px，hover 时 `foreground` @ 15% 高亮；双击重置 50/50；拖动时 cursor `IDC_SIZEWE` |
| 最小 pane | 20 列 × 5 行，不足时禁止继续分割 |
| 状态栏 | **不做常驻**。桌面层窗口的美学是「贴纸」，常驻状态栏破坏它。改为 hover 时右下角浮出信息角标（行列、编码、shell 名），1.5s 淡入 |

### 5.3 快捷键提示

不做常驻 cheatsheet。两个入口：

1. 首次运行 3s 内嵌提示（见 4.4）。
2. `Ctrl+Alt+/` 触发 overlay 浮层，列出键位，任意键关闭。

理由：常驻提示条占网格行，且与 shell 的输入区域争抢注意力；而 `Ctrl+Alt+/` 不会与 shell 键位冲突（`Ctrl+/` 会）。

## 6. 最小可行组件划分

### 6.1 分层与边界

| 层 | 组件 | 职责 | 明确不做 |
|---|---|---|---|
| 壳 | `win/window.rs` Surface | 生命周期、hit-test、拖动缩放、焦点事件 | 不认识 `Term`，不认识颜色 |
| 壳 | `win/layered.rs` Compositor | 透明度 / 圆角合成 | 不做布局 |
| 壳 | `win/workerw.rs` | 挂载与重挂 | — |
| 壳 | `win/dpi.rs` | PerMonitorV2、坐标换算 | — |
| 主题 | `theme.rs`（**新增**） | 16 色 + 语义槽 + 光标/选区/焦点，纯数据 | 不读 config、不碰 HWND |
| 呈现 | `render/layout.rs` | 网格几何：cell 尺寸、行列数、坐标换算 | 不做字体度量、不做绘制 |
| 呈现 | `render/glyph.rs` + `render/metrics.rs`（**新增**） | 字形缓存 + **fallback 链与 CJK 度量** | 不做排版 |
| 呈现 | `render/painter.rs` | 帧合成：网格 + 光标 + 选区 + overlay | 不做布局计算 |
| 呈现 | `render/cursor.rs`（**新增**） | 光标态机（实心/空心、闪烁、焦点） | 不参与 PTY 事件 |
| 呈现 | `render/selection.rs` | 选区模型与绘制 | — |
| 内容 | `term/session.rs` | PTY + 读线程 → channel | 不碰渲染 |
| 内容 | `term/grid.rs` | `Term` 封装，暴露脏行 / 视口 / 滚动偏移 | 不持有视觉态 |
| 内容 | `term/input.rs` | 键 → VT 字节 | — |
| 编排 | `app.rs` | 消息循环 ↔ 渲染节拍 ↔ 配置热重载 | 不写像素 |
| 配置 | `config/mod.rs`、`config/state.rs` | 校验、钳制、持久化 | — |

### 6.2 相对计划书的最小增量

只需新增 3 个文件职责，不新增模块：

| 新增 | 理由 |
|---|---|
| `theme.rs` | 计划书把颜色散在 config 与 painter 里；单点真源才能对 16 色做对比度单测 |
| `render/metrics.rs` | CJK fallback 度量是 M1-⑥ 的成败点，塞进 `glyph.rs` 会与缓存逻辑纠缠 |
| `render/cursor.rs` | 光标闪烁是**时间驱动**，必须与 PTY 事件解耦，否则大输出时闪烁卡死 |

### 6.3 三条硬边界（违反即返工）

1. **painter 不做布局**：所有像素坐标来自 `layout`。painter 里出现 `padding` 或 `cell_w` 的计算即为越界。
2. **时间驱动与内容驱动分离**：光标闪烁、hover 淡入用 `WM_TIMER`；16ms 节流只用于重绘合批，不得用来驱动状态。
3. **窗口壳不认识内容**：Surface 只向外广播「客户区尺寸变化」，由 `app.rs` 转成 layout 的入参。

## 7. 补充验收动作（可判定）

| 项 | 动作 | 通过标准 |
|---|---|---|
| 对比度 | 单测断言 `theme` 全槽位 vs `background` | 最小比值 ≥ 4.5:1 |
| 光标可读 | 块状光标停在汉字/字母上截屏 | 字符可辨（反色），非 1.14:1 的糊块 |
| CJK 对齐 | `printf '%-20s|%-20s|\n'` 与中文表格混排 | 第 2 列左边缘像素级对齐 |
| 网格稳定 | 125% DPI 下滚动 200 行 | 无逐行累积漂移、无字形抖动 |
| 焦点态 | Win+D → 观察光标 → 点击 | 空心 → 实心，描边出现 |
| 透明度下限 | `opacity = 0.5` + 纯白壁纸 | 若走路径 A 应被钳制到 0.75；路径 B 则正文仍可读 |
| 圆角 | 浅色/深色壁纸各截一张 | 圆角无锯齿、无 color key 残边 |
| 退出可达 | 让 `Ctrl+Alt+Q` 注册失败，再操作 | hover 出现 `×`，可退出 |
| 配置有效 | 逐项改 config 重启 | 每一项都有可见变化（无空转键） |

## 8. 待确认

1. **M4 走路径 A 还是 B**（决定 `border_radius` 去留与 +1～2 天）。建议 B。
2. **`Sarasa Mono SC` 是否接受作为默认 CJK fallback**（需随包分发或声明依赖，约 10–20MB；若不分发则退化为 YaHei 缩放方案，M1-⑥ 风险升高）。
3. **`opacity` 下限 0.75 是否接受**（若产品要求「更透」，则必须走路径 B）。
4. **hover `×` 是否违反「不在托盘显示、无关闭按钮」的原始需求**（我的理解是需求针对任务栏/托盘图标，窗口内 overlay 不在禁止范围；需确认）。
