## 0. 结论摘要

1. **不需要录屏也能覆盖 43 条中的 39 条**：屏幕捕获（`CopyFromScreen`/`BitBlt`）+ 窗口表面捕获（`PrintWindow`）+ **单像素探针序列**（`GetPixel` @30ms）+ 脚本化进程操作，组合起来能出硬数字。真正只能人工的只有 4 条（V-07/L3、V-14、V-27、V-33）。
2. **白壁纸最差条件有两条落地路径**：首选「白底衬底窗口注入同一 WorkerW」（零系统副作用、可秒级还原），次选「纯色壁纸切换 + 恢复注册表」。后者会被 Wallpaper Engine 覆盖，必须先停 WE。
3. **V-19 修法存在且不引入新依赖**：`CreateDIBSection` + `UpdateLayeredWindow`（纯 Win32，windows crate 现有 feature 足够）+ painter 增加 8bit alpha 平面 + 角部 4×4 超采样覆盖率。约 200 行，同时删掉 `softbuffer`（规范 §2.6 本来就预告了这一步）。若本轮不定，"降级说辞"见 §5.2。
4. **必须先修正两处证据文档缺陷**（否则 V-09/V-11 的断言值本身是错的）：见 §1.1、§1.2。
5. **V-19 / V-30 / V-32 三条改判为「有量化证据的不通过」**，不再写「未验」——不通过和不验是两种责任，前者有 owner、有复现路径。

## 1. 证据基线核查（先修文档，再采证据）

### 1.1 实现与契约的模型分歧（决定所有对比度阈值怎么算）

| 项 | 契约（spec §2.4/§2.6） | 实现（`win/layered.rs:1-11`） |
|---|---|---|
| 透明方式 | 逐像素 alpha（`UpdateLayeredWindow`），L0 背景透、L2 文字恒 α=1.0 | **整窗统一 alpha**（`SetLayeredWindowAttributes(LWA_ALPHA)`） |
| 圆角 | 圆角由逐像素 alpha 产生（自带 AA） | `SetWindowRgn(CreateRoundRectRgn)` **硬裁剪**，无 AA |
| 文字 | 永不稀释 | **随整窗一起稀释** |

**后果（必须写进 review）**：
- spec §2.5 的「0.72 断点」是**分层模型**的数字，整窗模型下的实测曲线是 plan §2.3（0.70 → 4.66:1，0.88 → 8.23:1）。两者不能混用；本方案全部按**整窗合成模型**判定：
  `合成色 = α·窗内色 + (1−α)·壁纸色`，其中 α 取**量化后的字节值**——`0.88 × 255 = 224.4 → 224`，即有效 α = **224/255 = 0.8784**，不是 0.88。判定时用 224，否则 V-02/V-03 会出现 0.02 级别的假偏差。
- 因此 V-01/02/03/06/38 **不能**用进程内渲染结果直接当证据（那是合成前的值），必须走屏幕捕获，或用 α 公式推导并标注为「推算值」。

### 1.2 网格数字不自洽（30 秒可核实，但必须先核实）

M5/index.md 同时写了「单元格 11×24 @130」和「900 宽下恒为 110 列」。按代码路径复算，这两者互斥：

```
DPI 130 → scale = 130/96 = 1.354
cell_w  = round(0.5859 em × 14px × 1.354) = round(11.10) = 11 px
cell_h  = round(14 × 1.25 × 1.354)        = round(23.70) = 24 px
padding = dpi::scale(10, 96, 130)         = 10×130/96 = 13 px   ← 整数截断，不是 round
客户区  = 900×420 物理像素（CreateWindowExW 直接用 config.window.width，未做 DPI 换算）
cols    = (900 − 26) / 11 = 79.45 → 79
rows    = (420 − 26) / 24 = 16.41 → 16
```

- 结论：130 DPI 下真实网格是 **79 × 16**，不是 110 列。**110 是 96 DPI 的列数**（plan §2.2 表里窗口尺寸是逻辑单位，应用里是物理单位，二者不可直接套用）。
- 现场核实（不改码，读日志即可）：
  ```powershell
  Get-Content "$env:LOCALAPPDATA\TLShell\logs\tlshell.log" |
    Select-String '字体就绪|启动完成' | Select-Object -Last 2
  # 期望看到：单元格 11x24 ；rect=900x420@(40,40); client=900x420; dpi=130
  ```
- 处置：V-09/V-10/V-11/V-13/V-15/V-17/V-18/V-21 的断言值全部改成 **@130 实测值**（cell 11×24、padding 13、radius 10 —— radius 也是 `dpi::scale(8,96,130)=10`，index 写的 8 是逻辑值）。plan §2.2「跨 DPI 列数 110 不变量」的措辞要改成「**窗口尺寸按逻辑单位缩放时**列数恒定」，否则它是一条假不变量。

### 1.3 命名漂移

plan §4.1 规定 `<序号>-<状态>-<DPI>-<壁纸>.png`（例 `03-focused-D150-L1.png`），M5 用的是 `05-ansi-and-cjk-130-desk.png`。新增证据一律用 plan 格式；旧文件不改名（保留可追溯性），在索引里加一列「实际文件名」。

## 2. 证据采集方案（E0–E3，全部本机可执行，不依赖录屏）

### E1（主路径）屏幕捕获 —— 唯一能判 alpha 合成与圆角 AA

```powershell
Add-Type -AssemblyName System.Drawing
$bmp = New-Object System.Drawing.Bitmap 900,420
$g   = [System.Drawing.Graphics]::FromImage($bmp)
# 窗口物理矩形 900x420 @ (40,40)：坐标每次由 GetWindowRect 读，不要硬编码
$g.CopyFromScreen(40,40,0,0,(New-Object System.Drawing.Size 900,420),
                  [System.Drawing.PixelFormat]::Format32bppArgb,
                  [System.Drawing.CopyPixelOperation]::SourceCopy)
$bmp.Save("$out\02-normal-D130-L1.png",[System.Drawing.Imaging.ImageFormat]::Png)
```

- **为什么必须屏幕捕获**：`SetWindowRgn` 是裁剪，圆角外**根本不存在窗口像素**，「角外露出的壁纸」只有在屏幕合成结果里才看得到。`CopyFromScreen` 取的就是 DWM 合成后的屏幕像素，正是判 V-19/V-20 需要的对象。
- 有遮挡/分层窗口抓不到内容时才用 P/Invoke `BitBlt(hdc, SRCCOPY|CAPTUREBLT)`；本实现是 `LWA_ALPHA`，合成结果为普通像素，`CopyFromScreen` 已够。
- 前置：桌面可见（`Win+D` 不会最小化桌面层窗口，这是它的设计），窗口矩形内无覆盖窗口；要白底先按 §2.1 铺底。

#### 2.1 白壁纸最差条件（L1）的三条实现路径

| 路径 | 做法 | 优势 | 风险/代价 | 建议 |
|---|---|---|---|---|
| **P1 推荐：白底衬底窗口注入同一 WorkerW** | 脚本建纯白（`#ffffff`）普通窗口 → `GetParent(TLShell.hwnd)` 拿同一个 WorkerW → `SetParent(白窗, workerw)` + `SetWindowPos(HWND_BOTTOM)` → 它就在壁纸之上、TLShell 之下的同一 z 序 → 抓图 → `DestroyWindow` 还原 | 确定性 #ffffff、不改壁纸、不动 Wallpaper Engine、秒级还原、可重复跑 | explorer 重启会掉；桌面图标（`SHELLDLL_DefView`）可能压在区域内 → 截图前「右键→查看→显示桌面图标」关掉，或把窗口挪到空桌面区 | **首选** |
| P2 纯色壁纸切换 | 生成 1×1 白 BMP → `SystemParametersInfo(SPI_SETDESKWALLPAPER, 0, path, SPIF_UPDATEINIFILE\|SPIF_SENDCHANGE)`；先存 `HKCU\Control Panel\Desktop\WallPaper` + `WallpaperStyle`，收尾写回并再发一次 SENDCHANGE | 最贴近「真实最差条件」，与用户所见一致 | **Wallpaper Engine 在场会用自己的窗口盖回去** → 必须先停 WE；改的是用户桌面，异常退出留脏状态；动态壁纸路径可能已失效 | 备用（WE 停掉时用） |
| P3 模型推导 | 用 §1.1 的 α 公式从 `PrintWindow` 结果算「白底期望值」 | 零采集成本 | **不是证据，只是交叉验证**；模型错就全错 | 仅作 sanity check |

**交叉验证规则**：任一条目上线前，先算「P3 推算值 vs P1/P2 实测值」，偏差必须 ≤ **2/255**（每通道）。超了先查模型（α 量化、DPI、主题是否被 config 覆盖），不许直接采信条目结论。

### E2（辅助）`PrintWindow(PW_RENDERFULLCONTENT=2)` 抓窗口自身表面

- 得到的是**窗口 DC 内容**，即 `softbuffer` 呈上去的那一帧：**不含** `LWA_ALPHA` 合成、**不受**遮挡与壁纸影响。
- 用途：(a) 几何/字距/行距/列对齐的可重复测量（V-09/10/11/12/13/15/16/17/21）；(b) 与 E1 同帧差分，分离「绘制错」与「合成错」。
- **明确不能用它判**：V-19/V-20（AA 与描边残留发生在合成侧）、所有对比度条目（不含 α）。

### E3（时序替代录屏）帧序列 + 单像素探针

**3.1 帧序列（伪录屏）**：先起捕获循环，再启动被测进程。

```powershell
# 只抓窗口矩形，16–33ms 一帧，落盘带时间戳
$sw=[Diagnostics.Stopwatch]::StartNew()
while($sw.ElapsedMilliseconds -lt 2000){
  $t=$sw.ElapsedMilliseconds
  $bmp=$script:grab.Invoke()          # 同 E1 的 CopyFromScreen
  $bmp.Save("$out\28-cold-$('{0:d4}'-f$t)ms.png")
  Start-Sleep -Milliseconds 17
}
```
- 覆盖 V-28/V-29（冷启动 0/16/33…ms）、V-26（点击后 ≤2 帧响应）、V-40（降级版，见 §3）。

**3.2 单像素探针（成本比 PNG 低 3 个数量级，且能出精确节奏）**：读光标格中心 + 四边共 5 点。

```powershell
# 光标格中心（130 DPI）：(padding + col*cell_w + cell_w/2, padding + row*cell_h + cell_h/2)
# 即 (13 + col*11 + 5, 13 + row*24 + 12)；30ms 一次，CSV: t_ms,center,top,bottom,left,right
```
- V-25：3 s 序列 → 周期 = 相邻「出现」间隔均值（期望 530ms，判 500–600），占空比 50%±10%。
- V-24：失焦下 1 s 序列恒定 **且** 中心点 ≠ cursor 色（说明是空心框）→ 通过。
- V-43：60 s 一次读「除光标格外的整行 strip hash」→ 30 min 内 hash 不变即通过（可无人值守）。

**3.3 输入注入的廉价替代**：`--config` 里给 `shell.args`，让待测输出**开机即出现**，全程零键盘注入：

```toml
[shell]
args = ["-NoLogo","-NoExit","-Command","1..10 | % { 'MMMM' }; dir C:\\; '中文路径 C:\\测试'"]
```
V-05（16 色 swatch）、V-09、V-11（`I`/`M` 串）、V-12（`dir` 表格）、V-15、V-16 都靠这条消除人工。

## 4. 必须人工目视的条目（4 条，不掩饰）

| 条目 | 为什么不能自动 | 人工时看什么 | 最小化人工的手段 |
|---|---|---|---|
| **V-27 IME 候选窗** | 候选窗由输入法进程创建，本机无脚本化 IME 路径；伪造 preedit 不等于真实输入法 | 候选窗左上角 vs 光标格偏差 ≤ 40 逻辑 px；不出屏下缘；不弹到 (0,0) | **人工触发 + 自动测量**：脚本守候截图，人打 3 个汉字，位置仍由像素算 |
| **V-14 字号可读下限** | 「笔画不粘连」无客观阈值 | size=12/13 下 `i`/`l`/`1` 是否可区分 | 先出代理指标（最小笔画间隙 px），人只做最终确认 |

## 5. V-19 圆角抗锯齿：可行修法与降级说辞

### 5.1 三条路，只有一条是修复

**M6-A 逐像素 alpha（正解；不引入新依赖，约 200 行）**

- 依赖核算：`CreateDIBSection` / `UpdateLayeredWindow` / `BLENDFUNCTION` 全在 `windows` crate 的 `Win32_Graphics_Gdi` + `Win32_UI_WindowsAndMessaging`（Cargo.toml 已启用）→ **不新增 crate**；反而**删除** `softbuffer`（spec §2.6 已预告）。
- 改动面（3 处）：
  1. `win/layered.rs` → 换成合成器：`CreateDIBSection(32bpp, BI_RGB)` + 预乘 BGRA + `UpdateLayeredWindow`（带 `prcDirty`）。
  2. `render/painter.rs` 的 `Frame` 增加一条 8bit **alpha 平面**：`put` 写 `α = opacity×255`，`blend_pixel` 写 `α = max(α_prev, 255×coverage)`，字形 α 恒 255。约 30 行。
  3. **AA 的真正来源**：在 α 平面上按 4×4 超采样解析圆角覆盖率（不要靠 GDI 区域），弧线自然得到 >3 级过渡。
- 附带收益（必须讲清，否则它只是"为了 AA 换架构"）：
  - spec §2.4 分层模型回归——文字不再被稀释，V-02 从 8.2:1 回到 **11.34:1**，V-38（白底选区）随之解套；
  - V-19/V-20 同时消项；
  - `opacity` 下限可以按 spec 的 0.30 重新讨论（整窗模型下 0.30 只有 1.3:1，根本不可读，这才是"加深壁纸限制"的真正原因）。
- 代价：推翻一次呈现路径（§6.3 硬边界不变，painter 仍不做布局）、要重跑 M4 全部玻璃证据。

**M6-B 只提升观感、不换合成（约 40 行，是降级不是修复）**

- 事实：矩形窗口 + 不做区域裁剪 ⇒ 四角是不透明背景，比硬边更糟；区域裁剪 + 硬边是当前架构下唯一可行组合。**AA 在 `LWA_ALPHA` 模型下没有解**。
- 只能做两件小事：`border_radius` 从 10（物理）降到 5，使阶梯从 10 段降到 5 段（读起来像"小圆角"而非"锯齿"）；`draw_border` 沿弧内侧让 1px 描边改用 `background`，避免描边把硬边强调出来。
- 必须在 README 与验收表同步标注为「**硬边小圆角**」。

**M6-C 系统圆角（零代码，但本场景不成立 —— 先验证再拒）**

- `DwmSetWindowAttribute(hwnd, DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUND)` 由 DWM 提供抗锯齿圆角，但**只作用于顶层窗口**；TLShell 挂载后是 WorkerW 的 `WS_CHILD`（`win/workerw.rs:181-188` 会把 `WS_POPUP` 强制换成 `WS_CHILD`）→ 挂载态无效。
- 唯一可用位置：`Attach::Fallback`（未挂载、顶层）分支。可作为降级态补丁，**不能作为 V-19 的通过证据**（验收态是挂载态）。

### 5.2 可直接写进验收表的降级说辞（本轮若不修，用这段）

> **V-19 圆角抗锯齿：不通过（已知架构偏差，P1）**
> 圆角由 `SetWindowRgn(CreateRoundRectRgn)` 做区域裁剪实现（`win/layered.rs:69-108`），边缘是硬边，无 alpha 过渡；130 DPI 下半径为 10 物理像素，弧线由约 10 段直角台阶构成，在浅色壁纸上可辨。
> 根因是呈现路径选了 `SetLayeredWindowAttributes(LWA_ALPHA)` 整窗 alpha，与 UI 规范 §2.6 要求的 B 路径（`UpdateLayeredWindow` 逐像素 alpha）互斥；AA 在该模型下无法实现，非参数调节问题。
> **改判条件**：M6 引入逐像素 alpha 合成器（§5.1 M6-A）后重测，四角采样需 ≥3 级中间亮度。在此之前本条保持不通过，不得记为"已知可接受"。

同时建议把 V-20 一并复测（硬边通常没有黑边，预期通过）——同一张图就能判，别浪费一次采集。
