## 0. 评审结论

「零 chrome 单窗口单会话」方向成立。6 处缺口中有 5 处已决策，剩余 G4 由「走 B 路径」消解。

| # | 缺口 | 状态 |
|---|---|---|
| G1 | ANSI 16 色未定义 | 已定（§2.3） |
| G2 | CJK fallback 度量未定义 | 已定（§3.2，Sarasa Mono SC 随包分发） |
| G3 | 焦点态无可视反馈 | 已定（§4.2） |
| G4 | `border_radius` 与整窗 alpha 互斥 | **已定：走逐像素 alpha，圆角成立**（§2.5） |
| G5 | 退出只有全局热键 | 已定：不加关闭按钮，改焦点内热键兜底（§4.5） |
| G6 | 窗口拖丢后无找回路径 | 已定（§4.5） |

**决策记录**

1. 透明实现走 **B 路径**（自绘 DIB + `UpdateLayeredWindow` 逐像素 ARGB）→ 圆角与文字不透明同时成立。
2. CJK fallback 采用 **`Sarasa Mono SC`**，随包分发。
3. **不接受 0.75 透明度下限**，需要更透 → 改为分层 alpha 模型，有效区间 [0.30, 1.0]（§2.4）。
4. **不要关闭按钮**，但需要 **Clear** 与 **New** 两个按钮（§4.4）。

## 1. 设计不变量

1. **文字永远不参与透明度稀释**。背景可透，字形 alpha 恒为 1.0。
2. **网格是唯一布局单位**。视觉元素只能落在整格上，或作为不参与布局的 overlay。
3. **焦点态必须可见**。桌面层窗口没有标题栏，焦点态是用户唯一能判断「能不能打字」的依据。
   **提权态必须可见且常驻**（与焦点态正交，见 4.2）——它是唯一能告诉用户「这个终端在管理员上下文」的线索。
4. **零常驻 chrome**。不占网格区域的 UI 只在 hover 时出现，且必须能自动消失。
   **例外**：提权描边与 `ADMIN` 标注必须常驻（4.2）。身份线索不是装饰，不受本条约束。
5. **配置项必须有可见效果**。不允许存在「写了但无效果」的配置键。
6. **控制条只做无害操作**。破坏性动作（重开会话）必须二次确认，且不用模态框。

### 2.2 对比度基线

| 组合 | 比值 | 判定 |
|---|---|---|
| `#cdd6f4` on `#1e1e2e` | **11.4 : 1** | 远超 AA |
| `#f5e0dc` on `#1e1e2e` | 13.0 : 1 | 光标块可辨 |
| `#1e1e2e` on `#f5e0dc` | 13.0 : 1 | 反色字符可读 |

**硬规则**：块状光标必须把格内字符用 `cursor_text` 重绘（反色）。若直接把前景色字符画在光标块上，1.14:1 等于字符消失。

### 2.4 分层 alpha 模型（低透明度方案）

用户要求更透，且不接受 0.75 下限。既然走逐像素 alpha，可以只让**背景**变透、文字始终锐利。五个图层各自带 alpha：

| 层 | 内容 | alpha | 说明 |
|---|---|---|---|
| L0 | 背景填充 | **`opacity`（0.30–1.0）** | 唯一随配置变化的层 |
| L1 | 选区 | 0.75 固定 | 不随 opacity，否则低透明度下选区消失 |
| L2 | 文字 | **1.0 固定** | 永不稀释 |
| L3 | 光标块 | 1.0 固定 | 格内字符用 `cursor_text` 重绘 |
| L4 | 控制条 / overlay | 1.0 固定 | 底板 `background` @ 0.92 |

`opacity` 默认 **0.65**，**仅出厂默认值，不是下限**。硬下限 **0.30**，硬上限 1.0。

- 下限 **0.30 硬编码，不可配置**。理由：低于此值窗口在深色壁纸上与桌面几乎不可区分，落入与「拖出屏幕」同类的「找不回来」问题（§4.5）。config 写入越界值时按 M3 既有钳制模式 clamp 到 0.30 并告警。
- 0.65 只是出厂默认，用户可自由下调到 0.30。
- 0.30 在深色壁纸下正文仍有约 **11.9 : 1**，可读性不是下限的约束条件；**可发现性**才是。

### 2.5 低透明度下的可读性断点

`#cdd6f4` 文字（alpha 1.0）压在 `background` @ α 之上、背后是纯白壁纸时，实测对比度：

| opacity | 白壁纸下正文对比度 | 判定 |
|---|---|---|
| 1.00 | 11.4 : 1 | ✓ |
| 0.88 | 8.2 : 1 | ✓ |
| 0.75 | 5.0 : 1 | ✓ |
| **0.72** | **4.5 : 1** | **精确断点** |
| 0.65 | 3.6 : 1 | ✗ 低于 AA |
| 0.50 | 2.6 : 1 | ✗ |
| 0.30 | 1.3 : 1 | ✗ |

**规范**：

1. `opacity ≥ 0.72` → 原样使用，任何壁纸下正文 ≥ 4.5:1。
2. `opacity < 0.72` → 自动启用**前景提亮**：`foreground` 按 `t = (0.72 − opacity) / 0.42` 在白化档位间插值（`#cdd6f4` → `#e6ebff` → `#ffffff`），ANSI 16 色同比提亮。这是纯数据变换，可单测。
3. 提亮后仍存在物理限制：**`opacity < 0.72` 只在深色壁纸下保证全 16 色可读**。浅色壁纸下 ANSI 0/8 这类暗色即使提亮也只有约 1.8:1。写进 README 已知限制，并给出建议：深壁纸可低至 0.35，浅壁纸用 ≥ 0.75。
4. 可选（v1.5）：启动时用 `SPI_GETDESKWALLPAPER` 取壁纸并采样窗口区域平均亮度，浅壁纸自动把 `opacity` 钳到 0.75 以上。v1 不做。

**为什么不加字形描边**：14px 字号 + 全向 1px 描边会让中文笔画粘连、字重失真。提亮是零成本的色彩变换，不碰字形缓存。这是本规范刻意选择。

#### 2.5.1 停留提亮（peek）—— 低透明度的可发现性兜底

`opacity < 0.45` 时启用：鼠标在窗口内**停留 600ms**（不是划过）后，背景 alpha 在 150ms 内升到 `min(1.0, opacity + 0.35)`；鼠标离开后 400ms 内回落到配置值。

- 触发条件是「停留」而非「进入」，避免鼠标划过桌面时窗口闪一下。
- 只在 `opacity < 0.45` 时生效；0.45 以上窗口本身可辨，peek 反而干扰。
- peek 只改 L0 背景 alpha，不动文字与选区。
- **这是 0.30 下限能成立的前提**：平时是极透的玻璃，需要看清时把鼠标停在上面。没有 peek 就只能把下限抬到 0.5 以上。
- 与控制条不冲突：peek 在 0.6s 触发，控制条在 1.5s 淡入，先后关系明确。

### 2.6 圆角与逐像素 alpha 的实现约束

B 路径的三个实现陷阱，写进 M4 任务说明：

1. **必须预乘 alpha**。`UpdateLayeredWindow` 配 `AC_SRC_ALPHA` 要求 BGRA 预乘。内部所有混合在预乘空间完成，否则圆角与字形边缘出现亮边/黑边。
2. **`softbuffer` 出局**。它不支持 layered window。改为自建 32-bit DIB section 直接绘制 → `UpdateLayeredWindow`。计划书 §4.1 的零件矩阵需更新：删除 `softbuffer` 依赖，新增约 150 行 DIB 与混合代码。降级为普通窗口时**不切换渲染路径**，只把 `opacity` 强制为 1.0，保持单路径。
3. **必须用脏矩形**。900×420 全窗约 1.5MB/帧，16ms 节流下约 94MB/s，偏高。`UpdateLayeredWindow` 的 `prcDirty` 只更新脏区。

## 3. 排版与网格规范

### 3.1 字体

| 项 | 值 | 说明 |
|---|---|---|
| 主字体 | `Cascadia Mono` | 系统自带，等宽，ASCII 覆盖好 |
| CJK 字体 | **`Sarasa Term SC`（内置，Regular + Bold）** | 终端专用版，CJK advance 严格 2×ASCII；字符集比 Sarasa Mono 更小、包体更省 |
| 系统兜底 | `Segoe UI Symbol` / `Microsoft YaHei UI` | **仅**覆盖内置字体缺字的罕见符号 |
| 字号 | 14.0 DIP | 配置项 |
| 行高 | 1.25 em = 17.5 DIP | 配置项 |
| Emoji | **不支持** | fontdue 只出 alpha 位图，彩色 emoji 成豆腐块 |

### 3.1.1 字体资产

| 项 | 决定 |
|---|---|
| 分发方式 | **随安装包内置**（用户已确认） |
| 打包 | `include_bytes!` 嵌入 exe。无安装器 + 单文件分发场景下路径最可控；代价是包体 +约 20MB、编译变慢、字体数据常驻内存 |
| 字重 | 只内置 Regular + Bold。fontdue 无合成 bold，缺 Bold 会让终端 bold 静默退化为 Regular |
| 许可证 | Sarasa Gothic 系 **SIL OFL-1.1**，随包分发需附完整许可证文本。与计划书 §11 风险 8（Alacritty `input.rs` 的 Apache-2.0）合并为**一份 NOTICE** |
| 度量锁定 | 记录字体文件 sha256 + 版本号。字体升级会静默改变 advance，直接破坏「CJK = 2 格」假设 → 表格错位。升级后必须重跑度量单测 |

### 3.2 CJK 对齐

`Cascadia Mono` 不含 CJK 字形。若 fallback advance ≠ 2 × ASCII advance，表格必然错位——正是 M1-⑥ 的验收点。

1. **CJK 走内置字体，不走系统 fallback**。`Sarasa Term SC` 的 CJK advance 严格等于 2×ASCII advance，表格对齐由字体设计保证，不需要运行时缩放。
2. **删除原「无 Sarasa 时按比例缩放字号」分支**。它是 M1-⑥ 的主要风险来源，随内置一起消失——这是选择内置的额外收益，不只是省一个安装步骤。
3. 系统 fallback 只处理内置字体缺字的罕见符号；命中时按 `cjk_px = size × 2 × ascii_advance_em / fallback_advance_em` 缩放，并**强制按 2 格对齐**（宁可字形轻微挤压，不可错格）。
4. East Asian Width：`W`/`F` → 2 格，`A` → 1 格（与 Windows Terminal 一致）。
5. 组合字符 / 变体选择符按 grapheme cluster 合成到一格，不逐码点占格。

### 3.3 网格几何

- **cell 尺寸取整到物理像素**。14px @125% DPI 的 advance 约 10.25px，留小数会累积漂移，右边缘字形抖动。
- 行高同样取整。换算点唯一：`render/layout.rs`。DPI 变化只改 layout，不改 glyph cache 的键。
- 参考值（900×420、padding 12、100% DPI）：cell ≈ 8×17，内容区 876×396 → **109 列 × 23 行**；125% DPI 约 **85 列 × 19 行**。
- 最小尺寸 **480 × 240**（约 58 列 × 13 行 @100%）。最大钳制到 WorkerW 客户区。

### 3.4 内边距

`padding` 默认 **12**，顶部比底部多 2px（无标题栏时等值 padding 视觉偏挤）。padding 计入 layout，不参与 hit-test（边缘 6px 仍归缩放区）。

## 4. 布局与状态规范

### 4.1 v1 可见层级

```
┌─────────────────────────────────┐  ← 无边框，圆角 8，逐像素 alpha
│  padding 12          [Clear][New]│  ← overlay，hover 才出现，不占布局
│  ┌───────────────────────────┐  │
│  │ 网格（唯一布局单位）109×23 │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

只有两层：**网格层** + **overlay 层**。overlay 含：控制条、IME 候选、一次性提示。

### 4.2 焦点态

| 状态 | 光标 | 描边 |
|---|---|---|
| 有焦点 | 实心块，`cursor` 填充 + 字符 `cursor_text` 反色，闪烁 530ms | 1px 内描边 `focus_ring` |
| 无焦点 | 1px 空心矩形，不闪 | 无描边 |

这是 Win+D 后「能不能直接打字」的唯一反馈。**M2 起必须实现**。

#### 4.2.1 提权态（与焦点态正交，M2 起实现）

`GetTokenInformation(TokenElevation)` 为真（进程以 high IL 运行，即用户从管理员 shell 启动 TLShell）时：

| 项 | 规格 |
|---|---|
| 描边 | **常驻 1px `elevated_ring`**，无论有无焦点都在 |
| 有焦点时 | `elevated_ring` 叠加 `focus_ring` 亮度（`elevated_ring` 提亮到 100%），仍为 1px，不叠加第二条线 |
| 无焦点时 | 只留 `elevated_ring` 1px（暗淡档），**不消失** |
| 标注 | overlay 右下角 `ADMIN` 字样，12px，`elevated_ring`，alpha 1.0，常驻 |
| 层级 | **固定在 L4**，alpha 1.0，**不随 `opacity` 稀释** |

两条硬约束：

1. **不随 opacity 稀释**。低透明度下（`opacity = 0.30`）L0 几乎透明，若描边跟着变淡，用户就失去了唯一的管理员线索（安全评审 S-07/S-20）。
2. **不得用「失焦消失」表达**。焦点态靠"消失"传达，提权态靠"颜色 + 常驻"传达，两种语义必须视觉可分——否则用户会把提权态误读成"这个窗口有焦点"。

为什么不做成图标/角标按钮：控制条 hover 才出现（4.4），把身份线索挂在 hover 上是自相矛盾的。描边是唯一零成本的常驻通道。

### 4.3 拖动 / 缩放 affordance

零 chrome 下没有可见边框，用 cursor shape 做零成本提示：

| 命中区 | 光标 | 行为 |
|---|---|---|
| 边缘 5px | `IDC_SIZEWE` / `IDC_SIZENS` / `IDC_SIZENWSE` / `IDC_SIZENESW` | 缩放 |
| 四角 16px | 对应斜向 | 缩放 |
| 内边距那一圈（≥12px） | `IDC_SIZEALL` | 拖动 |
| 标签栏按钮（`+` / `shell` / `清屏` / `×`）与标签本体 | `IDC_HAND` | 点击 |
| 标签栏空白处 | `IDC_ARROW` | 无 |
| 终端网格 | `IDC_IBEAM` | 选择 / 输入 |

**实现要点**：窗口类只带一个光标，所以不能靠 `WNDCLASSEXW.hCursor` 分派（类光标统一设成
`IDC_ARROW` 兜底）。`WM_SETCURSOR` 由窗口过程自己处理：用 `GetCursorPos` 取指针位置，
走一遍与 `WM_NCHITTEST` 完全相同的命中判定（同一套边距），再 `LoadCursorW` + `SetCursor`
设成对应形状，最后返回 1 表示已处理。`WM_MOUSEMOVE` 也要补刷一次——弹窗开合、按钮互切
这些状态变化发生时指针并没有移动，只靠 `WM_SETCURSOR` 会停在旧形状上。

### 4.4 控制条：Clear + New（无关闭）

**不做关闭按钮。** 退出走 §4.5。

#### 视觉规格

| 项 | 值 |
|---|---|
| 位置 | 右上角，距右 12px、距顶 12px（与 padding 对齐），横排 |
| 尺寸 | 24 × 24，圆角 4，间距 6 |
| 底板 | `background` @ 0.92 圆角底板，仅在 `opacity < 0.72` 时绘制（防图标与壁纸混色） |
| 图标 | 1.5px 线宽描边式，`control_icon`（`foreground` @ 60%） |
| hover | 按钮背景 `foreground` @ 12%，图标 @ 100% |
| 出现 | 鼠标进入窗口 1.5s 后淡入 200ms；离开 800ms 后淡出 200ms |
| **键盘输入立即隐藏** | 打字时按钮不得遮挡终端内容 |
| 隐藏时 | 完全不可点击，避免误触 |

#### Clear（本地清屏）

- **按钮宽度**：`清屏` 是两个汉字，按钮必须按 4 个单元格宽（`layout::CLEAR_W_CELLS`）排版，
  命中区同步放宽到半宽 + 4px。2 格宽的按钮会让两字压在一起，也让可点区域小于文字。
- **语义**：清 scrollback + 视口置空 + 光标回左上。**不向 PTY 发送任何字节。**
- **同时清除选区状态**：否则清屏后选区矩形仍浮在空视口上（视觉 bug，也让 `Ctrl+C` 的「有选区」判定失真）。
- 理由：`Ctrl+L` 已是 shell 侧清屏；若 Clear 也发 `ESC[2J`，在 vim / ssh 里会破坏 TUI 状态。本地清屏是纯视觉操作，语义安全。
- 副作用（写入 README）：shell 仍认为自己在原屏幕位置，PSReadLine 会在下次输出时重新定位，视觉上可能「跳一下」。可接受，优于破坏 TUI。

#### New（重开会话）

- **语义**：终止当前 PTY（含子进程），按 `config.toml` 起新 shell。等价于重置。
- 风险：vim / ssh 未保存内容丢失。无 chrome 下不弹模态框。
- **双击确认**：第一击进入 armed 态（背景 `yellow` @ 20%、图标变 `yellow`、右侧浮出 1.5s 文字「再次点击重开会话」）；1.5s 内第二击执行；超时回常态。单击误触不会丢数据，也不需要模态框。
- **armed 态复位条件**：鼠标离开按钮 / 窗口失焦 / 任意按键 → **立即**回常态。否则「点一下、去倒杯水、回来再点一下」就构成合法双击（安全评审 S-20：提权态下 `New` = 以管理员重生 shell）。

#### v2 冲突预留

标签条出现时，控制条迁到标签条右端与 `+` 并列，Clear / New 作用于**活动 pane**。v1 不必写占位代码，但 overlay 的锚点要从「窗口右上」改为「pane 右上」——这要求 `painter` 的 overlay 绘制接受一个 pane 矩形而非窗口矩形。v1 就按 pane 矩形写，成本为零。

### 4.5 退出与恢复（无关闭按钮的兜底）

- `Ctrl+Alt+Q` 全局热键。`RegisterHotKey` 可能因被占用而失败。
- **兜底**：注册失败时降级为**焦点内热键**——窗口有焦点时由 `WM_KEYDOWN` 捕获同一组合退出，**并消费该消息**（不得再转发给 shell，否则 shell 会收到一串 ESC 序列）。同时一次性在网格底部显示警告行（ANSI dim 色，PTY 有输出即消失）：「全局热键被占用，窗口内 Ctrl+Alt+Q 仍可退出」。
- `TLShell.exe --quit` 始终有效。
- **不加任何关闭 UI 元素。**
- **恢复路径**：`TLShell.exe --reset-position`；启动时若还原矩形与所有显示器无交集则回中。

### 4.5.1 切换终端（标签栏 `shell` 按钮）

点 `shell` 按钮**不直接切**：终端类型和「要不要新开」是两件事，一次点击说不清。改成弹一个两行菜单：

| 行 | 值 | 说明 |
|---|---|---|
| 终端 | `pwsh · PowerShell 7` / `powershell · Windows 5.1` / `cmd · 命令提示符` | 只列本机真能起来的候选（逐个试 `shell::resolve`），选不出来的是空白菜单 + 底部提示 |
| 方式 | `原地切换（保留记录）` / `新开标签（另起会话）` | 默认「原地切换」——用户抱怨的正是「切完记录没了」 |

- **键盘**：`↑↓` 选行、`←→` 改值、`Enter` 确认、`Esc` 取消。
- **鼠标**：点行 = 选中该行并把值推到下一个（与设置面板同一套「点一下翻一格」的手感），点弹窗以外的地方不穿透。
- **原地切换的语义**：只换 PTY，**不动 terminal**。屏幕内容、回滚历史、选区都不清空；分界线用一行 dim 提示「已切换为 X（上面这些记录没有清空）」。切到当前已经在跑的那个 shell 时什么都不重启，只提示「当前已经是 X」。
- **写配置**：只有终端真的变了才 `save_atomic`；保存失败退化为「只对本次运行有效」并提示。

### 4.6 首次运行提示

一次性，3s 淡出，用 ANSI dim 色画在网格底部，PTY 有输出即消失：
`拖动边缘缩放 · 拖顶部移动 · Ctrl+Alt+Q 退出`

### 4.7 IME（M5 预留）

中文 preedit 串必须在光标处绘制（下划线 + 候选窗跟随）。预留 `ImeOverlay` 组件位，即使 M5 前不实现也要在 painter 合成顺序里留出层级。

## 5. v2 代数预留（标签页 / 分屏 / 状态栏 / 快捷键提示）

### 5.1 布局模型

窗口 = **面板树**（split tree），叶 = session view；标签页 = 面板树上的「多根」层。

```
Window
 └ TabSet (v1 恒为 1 个 tab，不渲染标签条)
    └ Pane (v1 恒为单叶)
       └ SessionView = 网格 + overlay(以 pane 矩形为锚)
```

v1 的 `app.rs` 只持一个 `SessionView`。v1 唯一要保证的：网格渲染与 overlay 锚点都不假设自己占满客户区。

### 5.2 视觉规则（v2 生效）

| 元素 | 规格 |
|---|---|
| 标签条 | 高 28px，背景比内容区暗 8%；活动标签与内容区**同色**形成连通，非活动标签用 1px 下边线断开 |
| 标签标题 | shell 名或 cwd 尾段，最多 18 字符，中段省略 |
| 分屏分隔条 | 6px，hover `foreground` @ 15% 高亮；双击重置 50/50；cursor `IDC_SIZEWE` |
| 最小 pane | 20 列 × 5 行，不足时禁止继续分割 |
| 状态栏 | **不做常驻**。改为 hover 时右下角浮出信息角标（行列 / 编码 / shell 名），1.5s 淡入 |

### 5.3 快捷键提示

不做常驻 cheatsheet。两个入口：

1. 首次运行 3s 内嵌提示（§4.6）。
2. `Ctrl+Alt+/` 触发 overlay 浮层，任意键关闭。

用 `Ctrl+Alt+/` 而非 `Ctrl+/`，后者与 shell 键位冲突。

## 6. 最小可行组件划分

### 6.1 分层与边界

| 层 | 组件 | 职责 | 明确不做 |
|---|---|---|---|
| 壳 | `win/window.rs` Surface | 生命周期、hit-test、拖动缩放、焦点事件 | 不认识 `Term`，不认识颜色 |
| 壳 | `win/layered.rs` Compositor | DIB 分配、预乘混合、`UpdateLayeredWindow`、脏矩形 | 不做布局 |
| 壳 | `win/workerw.rs` | 挂载与重挂 | — |
| 壳 | `win/dpi.rs` | PerMonitorV2、坐标换算 | — |
| 主题 | `theme.rs`（**新增**） | 16 色 + 语义槽 + 分层 alpha + 低透明度提亮映射，纯数据 | 不读 config、不碰 HWND |
| 呈现 | `render/layout.rs` | 网格几何：cell 尺寸、行列数、坐标换算 | 不做字体度量、不做绘制 |
| 呈现 | `render/metrics.rs`（**新增**） | 字体度量 + fallback 链 + CJK 2 格对齐 | 不做排版 |
| 呈现 | `render/glyph.rs` | 字形光栅化缓存 | 不做排版 |
| 呈现 | `render/painter.rs` | 帧合成：L0–L4 五层 + overlay | 不做布局计算 |
| 呈现 | `render/cursor.rs`（**新增**） | 光标态机（实心/空心、闪烁、焦点） | 不参与 PTY 事件 |
| 呈现 | `render/selection.rs` | 选区模型与绘制 | — |
| 呈现 | `render/overlay.rs`（**新增**） | 控制条、提示行、IME 候选；锚点接受 pane 矩形 | 不占布局、不触发 resize |
| 内容 | `term/session.rs` | PTY + 读线程 → channel | 不碰渲染 |
| 内容 | `term/grid.rs` | `Term` 封装，暴露脏行 / 视口 / 滚动偏移 | 不持有视觉态 |
| 内容 | `term/input.rs` | 键 → VT 字节 | — |
| 编排 | `app.rs` | 消息循环 ↔ 渲染节拍 ↔ 配置热重载 ↔ 控制条动作分发 | 不写像素 |
| 配置 | `config/mod.rs`、`config/state.rs` | 校验、钳制、持久化 | — |

### 6.2 相对计划书的最小增量

新增 4 个文件职责，不新增模块：

| 新增 | 理由 |
|---|---|
| `theme.rs` | 颜色单点真源 + 低透明度提亮映射，才能对全槽位做对比度单测 |
| `render/metrics.rs` | CJK fallback 度量是 M1-⑥ 的成败点，塞进 `glyph.rs` 会与缓存逻辑纠缠 |
| `render/cursor.rs` | 光标闪烁是**时间驱动**，必须与 PTY 事件解耦，否则大输出时闪烁卡死 |
| `render/overlay.rs` | 控制条有自己的 hover / armed / 淡入淡出状态机，混在 painter 里会污染帧合成逻辑 |

计划书 §4.1 依赖矩阵同时变更：**删除 `softbuffer`**，新增自建 DIB（约 150 行）。

### 6.3 四条硬边界（违反即返工）

1. **painter 不做布局**：所有像素坐标来自 `layout`。painter 里出现 `padding` 或 `cell_w` 计算即越界。
2. **时间驱动与内容驱动分离**：光标闪烁、overlay 淡入用 `WM_TIMER`；16ms 节流只用于重绘合批，不驱动状态。
3. **窗口壳不认识内容**：Surface 只广播「客户区尺寸变化」，由 `app.rs` 转成 layout 入参。
4. **overlay 永不触发 resize**：控制条与提示只能画在已有网格之上，不得挤占网格导致 PTY 重排。

## 7. 补充验收动作（可判定）

| 项 | 动作 | 通过标准 |
|---|---|---|
| 对比度 | 单测断言 `theme` 全槽位 vs `background` | 最小比值 ≥ 4.5:1（opacity ≥ 0.72 档） |
| 提亮映射 | 单测 `opacity = 0.5` 的 theme 输出 | `foreground` 已提到白化档，ANSI 同比提亮 |
| 下限钳制 | config 写 `opacity = 0.1` | 启动钳到 0.30 并告警，窗口仍可发现 |
| 停留提亮 | `opacity = 0.30` + 深壁纸，鼠标停留 600ms | 背景明显加深，移开 400ms 内回落；划过不触发 |
| 内置字体度量 | 单测断言 `Sarasa Term SC` 的 CJK advance | 严格 == 2 × ASCII advance；不等则 M1-⑥ 直接失败 |
| 字体缺字兜底 | 输入内置字体缺字的符号 | 落系统 fallback 后仍占 2 格，不错格 |
| 光标可读 | 块状光标停在汉字/字母上截屏 | 字符可辨（反色），非 1.14:1 的糊块 |
| CJK 对齐 | `printf '%-20s\|%-20s\|\n'` 与中文表格混排 | 第 2 列左边缘像素级对齐 |
| 网格稳定 | 125% DPI 下滚动 200 行 | 无累积漂移、无字形抖动 |
| 焦点态 | Win+D → 观察光标 → 点击 | 空心 → 实心，描边出现 |
| 低透明度 | `opacity = 0.35` + 深色壁纸 | 正文与 ANSI 色均可读，无描边糊字 |
| 预乘 alpha | 圆角 + 白色壁纸截屏放大 | 圆角边缘无亮边/黑边 |
| 圆角 | 浅色/深色壁纸各截一张 | 圆角无锯齿、无 color key 残边 |
| 控制条不遮挡 | 打字过程中观察 | 键盘输入瞬间控制条隐藏 |
| Clear 语义 | 在 vim 内点 Clear | 屏幕清空，vim 状态未被破坏 |
| New 二次确认 | 单击 New | 进入 armed 态，不执行；1.5s 内再击才重开 |
| 热键兜底 | 让 `Ctrl+Alt+Q` 注册失败 | 焦点内同组合可退出，底部出现警告行 |
| 配置有效 | 逐项改 config 重启 | 每一项都有可见变化（无空转键） |

## 8. 决策状态

阻塞项已全部关闭。三条落地注意：

1. **`opacity`：默认 0.65，下限 0.30**。0.65 只是出厂默认，代码里不得把它当下限；`< 0.72` 触发前景提亮，`< 0.45` 额外触发停留提亮（peek）。
2. **`New`：双击确认**。armed 态 1.5s，超时回常态；单击绝不执行。
3. **`Sarasa Term SC` 内置**：需同时处理 OFL-1.1 NOTICE、字体 sha256 + 版本锁定、CJK 度量单测；系统 fallback 降级为「罕见缺字」路径。
